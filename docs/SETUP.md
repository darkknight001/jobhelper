# Setup guide

JobHelper finds jobs in India (Naukri, LinkedIn, company career sites, job-alert emails), scores them against your resume and notes, applies to the best matches, and tracks recruiter replies. It runs in one Docker container on a machine you own and reports to you on Telegram.

This guide takes about 45 minutes. One install is for one person: your resume, your accounts, your Claude subscription.

## What you need

| Need | Notes |
|---|---|
| An always-on Linux machine (home server, mini PC, VPS) | Docker with the Compose plugin. 4 GB RAM minimum, 8 GB comfortable (Chromium is the hungry part). About 5 GB disk. |
| A Claude Pro or Max subscription | Your own. Never share one between people. |
| A Gmail account with 2-Step Verification on | Needed for an app password. Job-portal mail must arrive here. |
| A Telegram account | For alerts and questions. |
| Naukri and LinkedIn accounts | Already set up, with your resume on them. |
| Optional: Tailscale, or a domain plus a reverse proxy (Caddy) | Only for using the dashboard from your phone. |
| Optional: Hermes | Not needed. Leave the Hermes variables empty. |

You also need `git` and `python3` on that machine (the setup script uses python3 to generate secrets). Claude Code (for `claude setup-token`) can be on any machine where you are logged in.

## 1. Get the code and run the setup script

```bash
git clone https://github.com/<owner>/JobHelper.git
cd JobHelper
scripts/setup.sh
```

Success: it prints `created deploy/.env`, `created data/profile.yaml`, `created data/kb/claims-policy.md` and `created config/settings.yaml`, then a short list of next steps. It never overwrites existing files, so re-running is safe.

The random secrets (session secret, API token, vault key, VNC password) are already filled in. Every `CHANGE_ME` value is yours to fill (step 5).

## 2. Get your Claude token

On any machine where Claude Code is installed and logged in to your own subscription:

```bash
claude setup-token
```

Copy the long token it prints. This is `CLAUDE_CODE_OAUTH_TOKEN`. It uses your plan's limits, not API credits. Treat it like a password.

## 3. Create a Gmail app password

1. Turn on 2-Step Verification: Google Account, Security.
2. Open Google Account, Security, 2-Step Verification, App passwords (or search for "App passwords").
3. Create one named `JobHelper`. Copy the 16 characters (spaces are fine).

JobHelper uses it only for read-only IMAP. If you do not see "App passwords", 2-Step Verification is off or your Workspace admin blocks it.

## 4. Create a Telegram bot

1. In Telegram, message `@BotFather` and send `/newbot`.
2. Pick a name and a username ending in `bot`.
3. Copy the token it gives you (looks like `123456:ABC-...`). This is `TELEGRAM_BOT_TOKEN`.

## 5. Fill in `deploy/.env`

```bash
nano deploy/.env
```

| Variable | What it is | Where to get it | Needed? |
|---|---|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | Lets JobHelper use your Claude plan | Step 2 | Required |
| `JOBHELPER_DASHBOARD_PASSWORD` | Password for the dashboard (no username) | Choose a long one | Required |
| `GMAIL_ADDRESS` | The Gmail that receives job mail | Your address, e.g. `you@gmail.com` | Required |
| `GMAIL_APP_PASSWORD` | Read-only mail access | Step 3 | Required |
| `TELEGRAM_BOT_TOKEN` | Your alert bot | Step 4 | Required |
| `JOBHELPER_PUBLIC_URL` | Address you open the dashboard at: `http://localhost:8095` on the same machine, or your `https://...` address behind a proxy | You decide | Required |
| `JOBHELPER_SESSION_SECRET` | Signs login cookies | Generated by setup | Pre-filled |
| `JOBHELPER_API_TOKEN` | Bearer token for the JSON API | Generated by setup | Pre-filled |
| `JOBHELPER_VAULT_KEY` | Encrypts saved career-site logins | Generated by setup | Pre-filled |
| `JOBHELPER_VNC_PASSWORD` | Password for the remote browser. Without it the browser stays locked | Generated by setup | Pre-filled |
| `JOBHELPER_BIND`, `JOBHELPER_CDP_PORT`, `JOBHELPER_HEADLESS` | Bind address, Chromium control port, visible browser | Leave as is | Leave |
| `HERMES_WEBHOOK_URL`, `HERMES_WEBHOOK_SECRET` | Fallback alert channel | Only if you run Hermes | Optional, leave empty |

Success: `grep CHANGE_ME deploy/.env` prints nothing. The file is private (mode 600); never commit or share it.

## 6. Start it

```bash
docker compose up -d --build
```

The first build downloads Chromium and Node and takes several minutes. Then check:

```bash
docker ps --filter name=jobhelper
docker logs --tail 30 jobhelper
```

Success: the container is `Up ... (healthy)` after about a minute, and the logs contain `Telegram bot connected`.

## 7. Open the dashboard and sign in

On the same machine, open `http://localhost:8095`. From another machine, forward the ports over SSH for now (permanent options are under "Phone access"):

```bash
ssh -L 8095:127.0.0.1:8095 -L 6080:127.0.0.1:6080 you@your-server
```

Then open `http://localhost:8095` on your own computer and sign in with `JOBHELPER_DASHBOARD_PASSWORD`.

## 8. Pair Telegram

1. Dashboard, Settings, "Telegram bot". It shows a six-character code and your bot's name.
2. In Telegram, open your bot and send `/start <code>`.
3. Reload Settings. It should say Paired. Press "Send test message".

After pairing, the bot answers only your chat and ignores everyone else.

## 9. Give it your resume, profile and rules

On the Knowledge page:

1. **Resume:** upload your PDF under Resumes. Add more variants if you have them; the scorer picks the best per job.
2. **Profile:** fill name, phone, CTC, notice period, education and so on. Any empty or `null` field makes the agent stop and ask you instead of guessing, so fill only what you are happy for it to submit.
3. **Claims policy:** edit `data/kb/claims-policy.md` (on the host, or from the Knowledge page). It holds the rules for what the agent may say about you. Replace every `<placeholder>` and delete what does not apply.
4. **Notes (valuable):** add short notes such as "Can join in 45 days". You can also have claude.ai write your career story using [claude-kb-export-prompt.md](claude-kb-export-prompt.md) and paste the answer under "Import from claude.ai". The command-line equivalent, with the file saved in `data/`:

```bash
docker exec jobhelper python -m jobhelper kb-import /app/data/export.md
```

The `data/` folder is mounted into the container, so editing `data/profile.yaml` and `data/kb/*.md` on the host also works.

## 10. Sign in to Naukri and LinkedIn once

JobHelper drives a real Chromium that stays logged in.

1. Dashboard, Settings, Browser: press "1 - Open portal logins". It opens the Naukri, LinkedIn and Indeed login pages.
2. Open the remote browser (noVNC). On the same machine or through the SSH forward, use:

```
http://127.0.0.1:6080/vnc.html?autoconnect=1&resize=scale
```

   (The "2 - Open remote browser" button is built for the reverse-proxy setup below and will not work on plain localhost.)
3. Enter `JOBHELPER_VNC_PASSWORD` when asked, then log in to each site in the browser you see. Solve any CAPTCHA or OTP yourself.

Sessions persist in `data/browser/`. Repeat if a portal logs you out.

## 11. Check everything

```bash
docker exec jobhelper python -m jobhelper doctor
```

Success: `claude` shows a working reply, `gmail` shows `ok (read-only login)`, `npx` shows a path. `hermes: not configured` is fine. Anything saying `FAILED` is covered in Troubleshooting.

Worth running once:

```bash
docker exec jobhelper python -m jobhelper verify
```

## 12. Customise `config/settings.yaml`

Setup copied `config/settings.example.yaml` to `config/settings.yaml`. The example is tuned for a senior backend engineer; change it to your field. It is re-read at the start of every run, so no restart is needed.

| Section | Change this |
|---|---|
| `candidate` | `years_experience`, `stretch_years` |
| `targets.roles` | Regexes for job titles you want |
| `targets.exclude_titles` | Titles to always drop |
| `targets.locations` | Cities (substrings) you accept |
| `search.keywords`, `search.locations` | What Naukri and LinkedIn are searched for |
| `ats_boards` | Company boards on Greenhouse, Lever, Ashby. Check with `docker exec jobhelper python -m jobhelper verify-boards` |
| `scoring` | `auto_apply_min` (default 85), `review_min` (60) |
| `apply.daily_cap_per_portal` | Default 10. Lower is safer |
| `apply.window_hours` | Hours (IST) in which it may apply |
| `llm` | Models per task; use cheaper ones if you hit limits |
| `schedule` | Times of discovery, apply and summary runs |

## 13. Watch a few runs, then go live

`apply.dry_run` is on by default: forms are filled but never submitted. With `hold_for_review` on, each filled form stays open in the remote browser until you press "I submitted it" or skip it.

1. Run one now:

```bash
docker exec jobhelper python -m jobhelper discover
docker exec jobhelper python -m jobhelper apply --max 1
```

2. Open the application in the dashboard and check each answer against your profile.
3. After a handful of correct runs, switch dry run off in Settings.

If an answer looks wrong, keep dry run on and fix the profile or claims policy first.

## Phone access, safely

The compose file publishes the dashboard (8095) and the remote browser (6080) on `127.0.0.1` only. Keep it that way. The remote browser is a logged-in session on your job accounts; anyone who reaches it can act as you. Never expose the dashboard or noVNC to the open internet.

Choose one:

1. **Reverse proxy with TLS, reachable only on your LAN or tailnet.** [deploy/Caddyfile.jobhelper](../deploy/Caddyfile.jobhelper) is an example: it serves the dashboard at `https://jobs.example.com` and `/vnc/*` only after the dashboard login (`forward_auth`). Its `import` lines come from the original server's own Caddy setup, so replace them with your own TLS arrangement. Then set `JOBHELPER_PUBLIC_URL=https://jobs.example.com` and run `docker compose up -d`.
2. **Tailscale.** Install it on the server and your phone, and put the reverse proxy above behind your tailnet name. This keeps everything private without opening any router port.
3. **SSH tunnel** (step 7) for occasional use.

Use `https` for any address other than localhost: login cookies are marked secure when `JOBHELPER_PUBLIC_URL` starts with `https`.

## Updating

```bash
cd JobHelper
git pull
docker compose up -d --build
```

Your `data/`, `config/settings.yaml` and `deploy/.env` are not touched. A rebuild restarts the browser.

From another machine (such as your laptop) to a server you can SSH into, with the repo and a Python venv (`.venv`) set up locally:

```bash
JOBHELPER_HOST=your-server scripts/deploy.sh
```

It runs the tests, stops if your local `config/settings.yaml` differs from the server's (add `--force` once you have checked), copies the code, rebuilds and re-runs the tests there. It expects the stack in `/opt/stacks/jobhelper` (override with `JOBHELPER_STACK`). `data/` and `deploy/.env` never leave the server.

### Backups

Everything personal is in `data/` (database, resumes, profile, knowledge base, browser sessions), plus `deploy/.env` and `config/settings.yaml`.

```bash
tar -czf jobhelper-backup-$(date +%F).tgz data deploy/.env config/settings.yaml
```

The backup contains logins and secrets. Keep it private and encrypted.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| `doctor` shows `claude: FAILED` | Token missing, expired, or pasted with a line break. Run `claude setup-token` again, update `CLAUDE_CODE_OAUTH_TOKEN`, then `docker compose up -d`. Needs an active Pro or Max plan. |
| `gmail: FAILED` | You used your normal password. Use the 16-character app password. Check `GMAIL_ADDRESS`, that 2-Step Verification is on, and that IMAP is enabled in Gmail settings (Forwarding and POP/IMAP). |
| `gmail: not configured` | `GMAIL_APP_PASSWORD` is empty. |
| No `Telegram bot connected` in logs | Wrong or missing `TELEGRAM_BOT_TOKEN`. Settings shows the error and keeps retrying. Fix the token, then `docker compose up -d`. |
| Pairing does nothing | Send `/start <code>` to your own bot with the current code from Settings, then reload. If paired to the wrong chat, press Unpair in Settings and pair again. |
| Remote browser will not connect, or is locked | `JOBHELPER_VNC_PASSWORD` is empty, so VNC refuses to start. Set it and restart. Check `docker logs jobhelper` for `x11vnc`. |
| Login keeps returning to the login page | `JOBHELPER_PUBLIC_URL` starts with `https` but you opened the site over `http`. Make them match. |
| An application stops: portal asked for login or a CAPTCHA | Log in again or clear the CAPTCHA in the remote browser (step 10), then Restart that application. |
| Nothing is scored or applied for a while | The usage governor pauses work near your Claude limits (`llm.governor` in settings; scoring stops first at 60 percent use). It resumes as the window resets. Use cheaper models or lower caps. |
| Telegram asks you a question | A required answer is not in your profile or notes. Answer it; it is saved for next time. |
| Dashboard unreachable from your phone | Ports are loopback-only by design. See "Phone access". |

Logs: `docker logs --tail 100 jobhelper`. Restart: `docker compose restart`.

## Costs and risks

- **Claude usage.** Scoring is cheap; applying is token-heavy (each application is a multi-turn browser run). JobHelper shares your subscription with your own Claude use. The governor pauses it before you run out, and `max_apply_runs_per_day` caps runs. There is no extra bill, but you can hit your plan limits.
- **Portal terms of service.** Naukri, LinkedIn and Indeed forbid automated applying. Daily caps, pacing and a real browser lower the chance of an account restriction but do not remove it. You accept this risk.
- **Wrong answers.** The agent answers only from your profile and notes and stops on anything it does not know, but check the first runs.
- **Keep dry run on** until you trust the answers.
- **Your data stays with you.** Resume, profile, mail and database live in `data/` on your machine. Text sent to Claude for scoring and form filling goes to Anthropic under your own account; alerts pass through Telegram.
